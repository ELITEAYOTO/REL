# REL roadmap and acceptance gates

Every item requires test evidence before the checkbox is marked complete. ADRs govern architecture changes.

## P0 — Foundational architecture — DONE

- [x] CLI-first modular workspace; separate contracts, parser and CLI.
- [x] Rust core; Python for future adapters; desktop postponed.
- [x] Initial security and provenance principles.

## P1 — Binary Inspector alpha — DONE within narrow scope

- [x] PE32 and PE32+ reading without executing inputs.
- [x] Sections, imports, exports, SHA-256 and JSON schema v1.0.0.
- [x] Corpus of two synthetic reference PEs, corruption tests and CLI overwrite guard.
- [x] Rust formatting, Clippy, unit/integration tests and release builds on Windows and Ubuntu.
- [x] CLI smoke test matches reference fixtures and validates JSON Schema.

**Evidence:** [PR #1](https://github.com/ELITEAYOTO/REL/pull/1) and [CI run 39096882395](https://github.com/ELITEAYOTO/REL/actions/runs/39096882395). **Do not interpret this as production readiness or universal PE correctness.**

## P1.5 — Binary Inspector hardening — IN PROGRESS (critical scope before pilot)

- [x] **P1.5-A declared data-directory count/capacity consistency (scoped CI verified):** reject PE32/PE32+ headers whose advertised 8-byte records cannot all fit in the declared optional header; public API and boundary tests. [PR #47](https://github.com/ELITEAYOTO/REL/pull/47), [Windows/Linux main CI #39173973900](https://github.com/ELITEAYOTO/REL/actions/runs/39173973900) and [bounded fuzz CI #39173751518](https://github.com/ELITEAYOTO/REL/actions/runs/39173751518) passed. Still not a parser CPU/RSS sandbox ([directory budgets](docs/security/P15A_DIRECTORY_BUDGETS.md)).
- [x] **P1.5-A Windows opened-handle identity (scoped CI-verified):** two guarded reads of the same path are compared using volume serial and Win32 FileIdInfo (128-bit). Intended to detect observable post-open redirection, without claiming the earlier path stat is identity-bound or that Windows ancestor traversal is atomic. [PR #45](https://github.com/ELITEAYOTO/REL/pull/45) and [main CI #39171804456](https://github.com/ELITEAYOTO/REL/actions/runs/39171804456) passed Windows/Linux. ## EX-01 — Experimental evidence/coverage envelope — AFTER CRITICAL P1.5-A

- [x] **EX-01 contract-only pilot (scoped CI verified):** independent experimental JSON Schema 0.1.0, standalone semantic validator, five controlled PE32 golden examples and explicit invalid-case tests; [PR #49](https://github.com/ELITEAYOTO/REL/pull/49), [Windows/Linux PR CI #39176105548](https://github.com/ELITEAYOTO/REL/actions/runs/39176105548), and [post-merge CI #39176279141](https://github.com/ELITEAYOTO/REL/actions/runs/39176279141) passed. This is **not** an extractor or complete EX-01; no v1 contract changes.
- [x] **EX-01 first controlled Rust producer (scoped Windows/Linux CI verified):** standalone `rel-observe dos-magic`, actual SHA/evidence, reproducible run ID and schema-validated integration tests on synthetic PE32/PE32+. [PR #51](https://github.com/ELITEAYOTO/REL/pull/51) and [post-merge main CI #39179499279](https://github.com/ELITEAYOTO/REL/actions/runs/39179499279) passed Windows/Linux. Limited to first two bytes, no behavior claims, not the full EX-01 feature.
- [x] **EX-01 controlled COFF Machine field domain (scoped CI verified):** two bytes at `e_lfanew + 4` with source SHA, independent offset/architecture and run-ID oracle, and `partial` / `indeterminate` for truncated machine fields. [PR #53](https://github.com/ELITEAYOTO/REL/pull/53) and [post-merge main Windows/Linux CI #39182313199](https://github.com/ELITEAYOTO/REL/actions/runs/39182313199) passed. This is not a complete PE parser.
- [x] **EX-01 declared PE section-header records (scoped Windows/Linux CI verified):** controlled, ≤2 MiB inputs; observe at most 32 COFF 40-byte records after declared optional-header bytes. Exact SHA-bound byte-offset evidence and independent Python oracle; `partial/indeterminate` for truncated tables and `unsupported` for over-limit counts. [PR #55](https://github.com/ELITEAYOTO/REL/pull/55) and [post-merge CI #39184367267](https://github.com/ELITEAYOTO/REL/actions/runs/39184367267) passed Windows/Linux. Does not validate mapped section payloads or whole PE.
- [x] **EX-01 source-backed evidence verification (scoped Windows/Linux CI verified):** independent Python checker validates file bytes, exact predicate/evidence values, source/run identity and partial/unsupported coverage semantics in three controlled EX-01 domains. Mutation-driven negative cases passed [PR #57](https://github.com/ELITEAYOTO/REL/pull/57) and [post-merge CI #39186361225](https://github.com/ELITEAYOTO/REL/actions/runs/39186361225) on Windows/Linux. This does not establish signatures/trusted publisher identity, atomic snapshots or sandbox security.
- [ ] Separate versioned observation schema: source hash, extractor/version/config, exact domain coverage, diagnostics and unknown states ([issue #14](https://github.com/ELITEAYOTO/REL/issues/14)).
- [ ] Golden tests for present/absent-in-scope/partial/failed/unsupported, invalid byte offsets, repeatability and v1 compatibility.
- [ ] Do not change `binary-manifest.schema.json` v1.0.0 or create speculative crates.
