# rel-diff — EX-02 experimental first slice

Compare two pre-generated **controlled PE** binary-manifest v1.0.0 JSON reports:

```sh
cargo run --locked -p rel-diff -- left.json right.json
```

The output is a separately versioned experimental JSON report governed by [manifest-diff.schema.json](../../contracts/experimental/manifest-diff.schema.json) (`0.1.0-experimental`). Size and architecture change flags, additions/removals of exact import/export strings, and metadata differences for uniquely named sections are compared. Section entries report added/removed/changed exact names with deterministic ordering. Output order is deterministic. Inputs must be regular files and are read from an opened file handle with a 16 MiB + 1 byte ceiling each, decoded with known fields, and extraction warnings or duplicate import/export strings fail closed. The opened handle is checked, avoiding a separate pathname metadata/open race; symlink targets that are regular files may still be followed. The bounded read is not a filesystem trust boundary or an overall memory/CPU sandbox. Section status reports `ambiguous` with no partial section deltas when either input repeats a section name. Otherwise comparison uses exact unique section names and flags changes to file offset, raw size or virtual address; a renamed section appears as removed plus added, not inferred as a rename. Unknown coverage is explicitly reported as a limitation; this is **not** a complete EX-02 implementation, exact JSON Schema validation, function diff, decompilation, security verdict or behavioral proof. Original manifest v1.0.0 stays unchanged.

The experimental `import_dll_case_only` boolean is true only if the exact import sets differ, but lowercasing **only the ASCII DLL prefix before `!`** makes the sets identical without any collisions within either report. Symbol names remain case-sensitive. `imports.added` and `imports.removed` always retain the **original strings**: the hint does not erase or reconcile evidence. False means either there was no raw change or this narrowly defined normalization could not establish case-only equivalence; it must not be interpreted as proof of a behavioral change. The hint covers the **entire** import set, not individual entries. It does not normalize paths, Unicode casing, DLL aliases, ordinal imports or malformed import strings.

Next gate: schema-complete validation, documented duplicate semantics, expanded normalization tests, representative golden fixtures, Windows/Linux CI, and benchmarks on authorized A/B builds. Do not promote EX-02 until those gates pass.

## Reproducible acceptance checks

Run `cargo test --locked -p rel-diff --all-targets` for the Rust unit and CLI tests. After building `rel-diff` in release mode and installing Python `jsonschema>=4,<5`, run `python scripts/test_manifest_diff_cli.py --binary target/release/rel-diff` (append `.exe` on Windows). This independent oracle exercises the **actual release CLI** with synthetic, contract-valid v1 inputs, validates every successful output against the separate experimental JSON Schema, and checks A/A, A/B, B/A, permutation invariance, repeated-byte determinism, casing collisions, ambiguous sections, invalid inputs and the 16 MiB size gate. The Windows/Linux CI runs it after the release build. It does not establish accuracy on real PE extraction, runtime behavior, memory bounds or a representative real-build benchmark.
